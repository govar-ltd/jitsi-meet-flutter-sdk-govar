The supported WebRTC configuration API temporarily applies the same default-mode preference to WebRTC itself; its previous global configuration is restored on fallback and teardown. Other mode requests and ambient teardown retain Jitsi behavior.

The official JitsiWebRTC 124.0.2 binary is unchanged. An image-scoped interceptor bypasses ordinary VoiceProcessingIO only for the candidate wide-range session. Existing running units are reconciled when Jitsi applies its configuration after start. No software AEC is added and no separate NS/AGC override is introduced.

The WebRTC global template explicitly preserves speaker routing when voiceChat becomes default. On route change, loss of availability/enabled state restores normal processing immediately. Recorder startup/status also checks for loss caused by competing capture and restores normal processing. Unsupported/rejected/unconfirmed routes retain standard system processing for the remainder of this conference. Live AudioUnits are tracked under a lock and removed before disposal. The RTC configuration lock precedes the policy lock; no session setter runs while the policy lock is held. Delayed fallback is generation-guarded against later conference teardown/reset.

Recorder/chunk/upload behavior unchanged. Diagnostics distinguish requested/available/enabled/confirmed, VPIO bypass, fallback reason and failures.
