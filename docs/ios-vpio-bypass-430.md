# WebRTC VoiceProcessingIO bypass experiment 430

Baseline: 429 SDK e9a3e7d, app f2467d2. That test held measurement for all 32 status samples but user still observed the approximately 12kHz cutoff. Keep 429's audio-mode adapter unchanged as control.

The public Objective-C API doesn't expose the internal AudioUnit. This experiment does NOT rebuild WebRTC or flip its C++ factory boolean. Instead, an image-scoped fishhook adapter changes only WebRTC.framework/WebRTC imports of AudioUnitInitialize, AudioUnitSetProperty and AudioOutputUnitStart. It uses public AudioUnit APIs on the actual unit and only for subtype VoiceProcessingIO. Other framework/application imports and unit types pass through unchanged.

After successful native initialization: request kAUVoiceIOProperty_BypassVoiceProcessing=1 on global/input bus 1, as M124 does, read back the result, disable AGC only if bypass was confirmed. Subsequent RTC AGC writes are held at zero only while bypass reads as one. If bypass is refused/unreadable, retain normal gain behavior and preserve successful original initialization. Original init/start errors are returned unchanged. Read flags again immediately after actual unit start; a reset by the system is logged, not reported as confirmed bypass. Every reinitialization repeats the request. No additional microphone source, AudioUnit render interception or real-time sample processing is introduced.

Guards: resolve system functions first; match only loaded /WebRTC.framework/WebRTC; require successful rebinding writes for all three imports before enabling behavior. Missing image, partial rebinding or protection failure keeps wrappers as pass-through. No global rebind registration. Original public API pointers come from dlsym rather than potentially unresolved lazy-binding slots.

Native JSON diagnostics include installed/failure, import write counts, VPIO init/start counts, verified bypass init/start counts, last init/start/set/read statuses, last bypass/AGC readbacks. These readbacks are snapshots at init/property writes/start, not continuous reads on every five-second diagnostic tick; don't retain/dereference a potentially disposed AudioUnit from the main thread.

Vendor: facebook/fishhook aadc161ac3b80db07a9908851839a17ba63a9eb1, BSD license retained and bundled as ios/Assets/GovarWebRTCBypass-fishhook-LICENSE.txt. Local modifications namespace functions and count actual successful writes. Internal SDK/import layout remains version-specific; guards are mandatory on SDK upgrades.

Validation: actual Mach-O image-only import rebinding against a mock WebRTC dylib; forward other API calls/images/unit types; bypass/gain behavior, readback failures, rejected bypass, init/start failures, system reset at start, idempotence, missing image and partial rebinding. iOS Objective-C syntax and Swift typecheck passed. Existing three native AudioMode scenarios and five continuous WAV/PCM splitter tests passed. These do NOT prove iOS hardware honored bypass or that the parallel AVAudioRecorder signal is full-band.

Recorder format and flow unchanged: one continuous AVAudioRecorder WAV PCM16 48kHz mono, Dart sample splitting first 10s then 60s, final tail and existing uploads. No Android changes. Test on iPhone: built-in microphone/no Bluetooth; 90–120s with peer, check echo, gain and intelligibility, mute/video, routes, rejoin/reconnect; inspect actual post-start bypass=1/AGC=0 and statuses, spectra and WAV seams. Bypass can increase echo and does not guarantee wider capture. Hardware results pending; direct installation only, no store upload.
